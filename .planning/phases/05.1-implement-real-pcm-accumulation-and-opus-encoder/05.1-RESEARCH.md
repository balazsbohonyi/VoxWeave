# Phase 5.1: Implement Real PCM Accumulation and Opus Encoder - Research

**Researched:** 2026-03-20
**Domain:** Rust audio capture (cpal), resampling (rubato), Opus encoding (audiopus + ogg), Tauri structured logging
**Confidence:** HIGH

## Summary

Three stubs block real transcription: `synthetic_capture_pcm()` returns silence, `DefaultEncoderBackend::encode_opus()` returns a fake Ogg header, and `log::` calls emit nowhere. The existing `start_realtime_level_capture` cpal thread handles RMS but discards PCM — it needs to also send PCM chunks via an mpsc channel to an accumulator buffer. At stop time, the accumulated `Vec<f32>` (already 16kHz mono after resampling in-thread) replaces the synthetic stub. The `encode_opus` stub is replaced by a real audiopus + ogg mux pipeline.

All three chosen libraries (audiopus 0.2, ogg 0.9, tauri-plugin-log 2.0) have verified APIs that fit directly into the existing architecture without structural changes. The cpal callback pattern, EncoderBackend trait, and `#[cfg(not(test))]` guards remain unchanged. The rubato 1.x API has changed from `SincFixedIn`/`FftFixedIn` to unified `Async`/`Fft` types — use the current 1.x API, not pre-1.0 examples.

**Primary recommendation:** Extend the existing cpal capture thread in-place (add mpsc PCM sender alongside the atomic RMS), resample as chunks arrive using `rubato::Fft`, accumulate into `Arc<Mutex<Vec<f32>>>` visible to `AudioSessionState`, replace the Opus stub with audiopus+ogg, and wire `tauri-plugin-log` into the existing `.plugin()` chain.

### Pattern 1: PCM Accumulation in cpal Callback Thread

**What:** The existing capture thread already computes RMS via `AtomicU32`. Add a second accumulation path: send each converted PCM chunk to a `crossbeam` or `std::sync::mpsc` channel. A separate lightweight loop (or the same thread after resampling) pushes into `Arc<Mutex<Vec<f32>>>`.

**When to use:** Single stream, dual purpose — avoids opening two cpal streams on the same device (which fails on some Windows WASAPI drivers).

**How it works in the existing code:**
- `start_realtime_level_capture` spawns a thread that owns the cpal `Stream`
- The callback closure currently calls `update_latest_rms(data, &rms_for_callback)`
- Extend the callback to also call a PCM sender
- The emitter loop at the bottom of the thread (`while !stop_for_thread`) can drain an mpsc receiver into the accumulation buffer after each RMS emit, OR the callback sends directly to an `Arc<Mutex<Vec<f32>>>`

**Resampling approach:**
- Read `stream_config.sample_rate.0` at stream open
- If `sample_rate == 16000`, skip resampling — pass chunks directly
- Otherwise, create a `rubato::Fft` resampler (input_rate → 16000) once and reuse per chunk

**5-minute cap enforcement:**
- Track accumulated sample count (after resampling, all samples are 16kHz)
- Threshold: `5 * 60 * 16_000 = 4_800_000` samples for hard stop
- Threshold: `4.5 * 60 * 16_000 = 4_320_000` samples for `recording-near-limit` event

**Pattern 2: Real Opus Encoder in DefaultEncoderBackend**

**What:** Replace the stub in `encode_opus` with audiopus + ogg muxing.

**Key facts verified:**
- `audiopus::coder::Encoder::new(SampleRate::Hz16000, Channels::Mono, Application::Voip)` — correct for voice
- `encoder.encode_float(input_frame: &[f32], output: &mut [u8]) -> Result<usize>` — returns encoded byte count
- Frame size at 16kHz mono: 20ms = **320 samples** per frame
- Input length must be exactly N × frame_size; pad the final frame with zeros if short
- Output buffer: 4000 bytes is ample for a 20ms opus frame at 24kbps
- Bitrate: `encoder.set_bitrate(Bitrate::BitsPerSecond(24_000))` — standard for voice

**Ogg muxing with ogg 0.9:**
```rust
// Source: docs.rs/ogg/0.9.2/ogg/writing/struct.PacketWriter.html
use ogg::writing::{PacketWriter, PacketWriteEndInfo};
let mut pw = PacketWriter::new(output_cursor);
// For each Opus packet:
pw.write_packet(opus_bytes, serial, PacketWriteEndInfo::NormalPacket, granule_pos)?;
// Final packet:
pw.write_packet(last_opus_bytes, serial, PacketWriteEndInfo::EndStream, final_granule)?;
```

**Ogg/Opus requires an OpusHead and OpusTags packet before audio data** — both are fixed-format identification packets required by the Opus-in-Ogg spec. The header encodes sample rate, channel count, and pre-skip.

**Pattern 3: tauri-plugin-log Integration**

**What:** Add the plugin to the Tauri builder before `setup`. Wire `#[cfg(debug_assertions)]` / `#[cfg(not(debug_assertions))]` for log level.

```rust
// Source: tauri-plugin-log 2.0.0 docs
use tauri_plugin_log::{Builder as LogBuilder, Target, TargetKind};

// In lib.rs run():
let log_level = if cfg!(debug_assertions) {
    log::LevelFilter::Debug
} else {
    log::LevelFilter::Info
};

tauri::Builder::default()
    .plugin(
        LogBuilder::new()
            .level(log_level)
            .targets([
                Target::new(TargetKind::Stdout),
                Target::new(TargetKind::LogDir { file_name: None }),
                Target::new(TargetKind::Webview),
            ])
            .build(),
    )
    // ... existing plugins
```

`TargetKind::LogDir` defaults to `%APPDATA%\{app-name}\logs\` on Windows. `file_name: None` uses the default (`app.log`). No rotation needed for v1.

### Anti-Patterns to Avoid

- **Two cpal streams on one device:** Opening a second stream for PCM while the first does RMS causes WASAPI exclusivity failures on many Windows machines. Use one stream that does both.
- **Resampling at stop time on the full buffer:** Resampling 5 minutes of 48kHz audio at stop time adds 100ms+ latency to transcription start. Resample per-chunk in the callback thread.
- **Non-frame-aligned Opus input:** Passing arbitrary-length PCM to `encode_float` causes `OpusError::BadArg`. Always use fixed 320-sample (20ms at 16kHz) chunks; zero-pad the final frame.
- **Skipping OpusHead/OpusTags Ogg packets:** Groq/OpenRouter will reject the file. These identification headers are mandatory per RFC 7845.
- **Holding Mutex across await:** The existing code has explicit `MutexGuard` drops before spawning async tasks — follow this pattern when accessing `pcm_buffer` in the stop path.
- **log! calls before plugin init:** The log plugin must be added to the builder before `setup` runs. If added inside `setup`, early-phase log calls are lost.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| PCM → Opus frames | Custom Opus wrapper | audiopus | libopus has 3000+ lines of complexity; frame alignment, bitstream format, and per-packet state are non-trivial |
| Ogg container | Custom Ogg muxer | ogg 0.9 | Ogg requires CRC32 per page, granule position tracking, serial number management |
| Resampling | Linear interpolation | rubato | Linear interpolation introduces aliasing artifacts that degrade speech recognition accuracy; sinc/FFT required |
| OpusHead packet | Manual byte packing | Hardcode per spec | The 19-byte OpusHead is documented in RFC 7845 §5.1 — hand-craft once, don't derive |

**Key insight:** Resampling and Opus frame encoding have hidden correctness requirements (aliasing, frame alignment, pre-skip, granule position) that cause silent quality degradation rather than hard errors.

## Common Pitfalls

### Pitfall 1: rubato 1.x API is Different from Pre-1.0
**What goes wrong:** Pre-1.0 examples use `SincFixedIn::new(...)` and `process(&input, None)`. These are compile errors in rubato 1.x.
**Why it happens:** rubato 1.0 unified to `Fft` and `Async` types with new constructor signatures.
**How to avoid:** Use `rubato::Fft::<f32>::new(native_rate, 16_000, chunk_size, 2, 2, FixedSync::Input)` (or similar). Read rubato 1.x docs, not StackOverflow answers that predate 1.0.
**Warning signs:** Compile error "no struct `SincFixedIn`".

### Pitfall 2: Opus Frame Size Must Match Encoder Configuration
**What goes wrong:** Passing 160 samples (10ms) when encoder was configured for 20ms frames returns `OpusError::BadArg` silently discarded or panics.
**Why it happens:** Opus encodes in fixed frames; the encoder is stateful.
**How to avoid:** Choose frame size once (320 samples = 20ms at 16kHz), buffer incoming PCM until a full frame is available before calling `encode_float`.
**Warning signs:** All `encode_float` calls return error or produce empty output.

### Pitfall 3: Missing OpusHead / OpusTags Identification Headers
**What goes wrong:** Groq or OpenRouter returns a decode error or 400 for the audio file.
**Why it happens:** Ogg/Opus spec (RFC 7845) mandates two identification packets before any audio data. The `ogg` crate is a generic Ogg muxer — it doesn't know about Opus and won't insert these automatically.
**How to avoid:** Write OpusHead (19 bytes, serial 0, granule 0, `EndPage` end info) and OpusTags (minimal comment header, `EndPage`) as the first two logical packets before any audio frames.
**Warning signs:** Transcription API returns HTTP 400 "invalid audio format" or "cannot decode ogg".

### Pitfall 4: PCM Buffer Grows Unbounded Without Cap Enforcement
**What goes wrong:** A user who forgets to stop recording fills memory. At 16kHz f32, 5 minutes = 19.2 MB — tolerable, but 30 minutes would be 115 MB.
**Why it happens:** Accumulator has no stop condition without explicit cap logic.
**How to avoid:** Track sample count in capture thread. At 4,800,000 samples, set `stop_for_thread` flag and emit `recording-near-limit` event at 4,320,000. The same AtomicBool stop path already used for level capture handles this.
**Warning signs:** Memory grows monotonically during long recordings.

### Pitfall 5: tauri-plugin-log Capability Permission Missing
**What goes wrong:** Webview target produces a `permission denied` error; logs don't appear in devtools.
**Why it happens:** Tauri v2 capabilities system requires explicit permission grants.
**How to avoid:** Add `"log:default"` to `capabilities/default.json` permissions array.
**Warning signs:** Log plugin initializes without error but Webview target is silent.

### Pitfall 6: Short Recording Below Minimum Threshold
**What goes wrong:** Encoding 50ms of audio (800 samples) into Opus produces an essentially empty or near-empty file that transcription providers reject or return empty text for.
**Why it happens:** Very short recordings are user accidents (accidental hotkey double-tap).
**How to avoid:** Keep the Phase 3 short-audio decision: warn and drop if accumulated samples < threshold (e.g. < 0.5s = 8,000 samples). This is Claude's discretion per CONTEXT.md.

## Code Examples

### Opus Encoder Setup (audiopus 0.2)
```rust
// Source: docs.rs/audiopus/0.2.0/audiopus/coder/struct.Encoder.html
use audiopus::coder::Encoder;
use audiopus::{Application, Channels, SampleRate, Bitrate};

let mut encoder = Encoder::new(
    SampleRate::Hz16000,
    Channels::Mono,
    Application::Voip,
).map_err(|e| e.to_string())?;
encoder.set_bitrate(Bitrate::BitsPerSecond(24_000)).map_err(|e| e.to_string())?;
```

### Encoding One 20ms Frame
```rust
// 20ms at 16kHz mono = 320 samples
const FRAME_SIZE: usize = 320;
let mut output_buf = vec![0u8; 4000];
let encoded_len = encoder
    .encode_float(&frame_320_samples, &mut output_buf)
    .map_err(|e| e.to_string())?;
let opus_packet = &output_buf[..encoded_len];
```

### Ogg/Opus OpusHead Packet (RFC 7845 §5.1)
```rust
// Minimal OpusHead for mono 16kHz, pre-skip=312 (standard), output gain=0
fn make_opus_head() -> Vec<u8> {
    let mut h = Vec::with_capacity(19);
    h.extend_from_slice(b"OpusHead");       // magic
    h.push(1);                               // version
    h.push(1);                               // channel count (mono)
    h.extend_from_slice(&312u16.to_le_bytes()); // pre-skip
    h.extend_from_slice(&16_000u32.to_le_bytes()); // input sample rate
    h.extend_from_slice(&0i16.to_le_bytes()); // output gain
    h.push(0);                               // channel mapping family
    h
}
```

### Ogg/Opus OpusTags Packet (minimal)
```rust
fn make_opus_tags() -> Vec<u8> {
    let vendor = b"VoxWeave";
    let mut t = Vec::new();
    t.extend_from_slice(b"OpusTags");
    t.extend_from_slice(&(vendor.len() as u32).to_le_bytes());
    t.extend_from_slice(vendor);
    t.extend_from_slice(&0u32.to_le_bytes()); // 0 user comments
    t
}
```

### Ogg Muxing Loop
```rust
// Source: docs.rs/ogg/0.9.2/ogg/writing/struct.PacketWriter.html
use ogg::writing::{PacketWriter, PacketWriteEndInfo};
use std::io::Cursor;

let mut output = Cursor::new(Vec::new());
let mut pw = PacketWriter::new(&mut output);
let serial: u32 = rand::random(); // or a fixed value

// Identification headers (must be on separate pages per RFC 7845)
pw.write_packet(make_opus_head(), serial, PacketWriteEndInfo::EndPage, 0)?;
pw.write_packet(make_opus_tags(), serial, PacketWriteEndInfo::EndPage, 0)?;

// Audio frames
let mut granule: u64 = 0;
for (i, chunk) in pcm.chunks(FRAME_SIZE).enumerate() {
    let frame = if chunk.len() == FRAME_SIZE {
        chunk.to_vec()
    } else {
        let mut padded = chunk.to_vec();
        padded.resize(FRAME_SIZE, 0.0);
        padded
    };
    let mut buf = vec![0u8; 4000];
    let n = encoder.encode_float(&frame, &mut buf).map_err(|e| e.to_string())?;
    granule += FRAME_SIZE as u64;
    let is_last = i == num_frames - 1;
    let end_info = if is_last {
        PacketWriteEndInfo::EndStream
    } else {
        PacketWriteEndInfo::NormalPacket
    };
    pw.write_packet(buf[..n].to_vec(), serial, end_info, granule)?;
}
let ogg_bytes = output.into_inner();
```

## Open Questions

1. **rubato 1.x exact constructor for fixed-input chunked resampling**
   - What we know: `Fft::<f32>::new(in_rate, out_rate, chunk_size, oversampling, channels, FixedSync)` from docs
   - What's unclear: exact `FixedSync` variant to use for "fixed input size" mode (vs fixed output)
   - Recommendation: Use `FixedSync::Input` if that variant exists; otherwise verify at implementation time by reading rubato 1.x module docs directly.

2. **Pre-skip value in OpusHead**
   - What we know: 312 is a standard pre-skip value for 20ms frames at 48kHz; at 16kHz the encoder may report a different value
   - What's unclear: audiopus 0.2 does not expose a `get_lookahead` method in the high-level API; may need to read from the underlying encoder
   - Recommendation: Use 312 as the hardcoded pre-skip (acceptable for transcription use — pre-skip only affects playback start offset, not recognition accuracy).

3. **Short-audio minimum threshold value**
   - What we know: Phase 3 decision is "warn and drop" for very short recordings; exact threshold is Claude's discretion
   - Recommendation: 0.5 seconds = 8,000 samples at 16kHz. Below this, emit a warning toast and return early before encoding.
