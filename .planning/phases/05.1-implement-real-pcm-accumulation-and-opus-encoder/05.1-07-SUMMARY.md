# Phase 05.1 Plan 07: Drop OpenRouter, Add Provider Selector Summary

**OpenRouter removed from codebase. Active provider now selectable from the Settings window. Groq confirmed working.**

## Background

Two issues were discovered through user testing:

1. **OpenRouter dropped**: OpenRouter has no Whisper-style STT endpoint. The implementation used chat completions with base64-encoded audio, which produced inconsistent results and is not purpose-built for dictation. The user confirmed this after testing.

2. **Provider not selectable**: The `transcription.provider` field in config.json controlled the active provider, but there was no Settings UI for it. Users who edited `fallback_order` (thinking it determined which provider ran first) saw no effect because `provider` and `fallback_order` are separate concerns — `provider` is the active provider, `fallback_order` is only tried on failure.

## Accomplishments

### OpenRouter removal
- Deleted `src-tauri/src/transcription/openrouter.rs`
- Removed `TranscriptionProvider::Openrouter` variant from enum in `config/mod.rs`
- Removed `openrouter_api_key` and `openrouter_model` fields from `TranscriptionConfig`
- Removed `base64` crate from `Cargo.toml` (only used by openrouter.rs)
- Updated `default_fallback_order()` to `[Openai, Groq]`
- Cleaned up all `Openrouter` match arms in `service.rs`, `encode.rs`, `provider.rs`, `commands/transcription.rs`
- Updated affected tests (65/65 passing)

### Provider selector in Settings
- Added `Provider` dropdown (OpenAI / Groq) to Settings window
- Saves immediately on change — consistent with language selector pattern
- Reads from and writes to `transcription.provider` in config

### Documentation
- `CLAUDE.md` Key Decisions: added OpenRouter exclusion decision and `provider` vs `fallback_order` distinction note for Phase 8
- `.planning/PROJECT.md`: updated requirements and context to remove OpenRouter references

## Backward Compatibility

Existing `config.json` files with `openrouter_api_key`, `openrouter_model`, or `"provider": "openrouter"` are handled gracefully:
- `openrouter_api_key` / `openrouter_model` become unknown fields — ignored by serde, preserved by the raw JSON round-trip in persistence.rs
- `"provider": "openrouter"` fails `FromStr` → config falls back to `TranscriptionProvider::default()` (OpenAI)

## Note for Phase 8 (Full Settings UI)

The distinction between `transcription.provider` (active provider) and `transcription.fallback_order` (failover chain) must be made explicit in the Phase 8 Settings UI. These are separate concerns and users confused them when editing config.json directly.
