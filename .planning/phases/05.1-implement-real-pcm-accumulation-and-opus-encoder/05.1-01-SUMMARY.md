# Phase 05.1 Plan 01: PCM Accumulation and Real Audio Drain Summary

**One-liner:** Replaced `synthetic_capture_pcm()` stub with real-time 16kHz mono PCM accumulation in the cpal capture thread, with integer decimation downsampling, 5-minute hard cap, and a drain-on-stop path.

## What Was Built

The capture thread now accumulates real microphone PCM during recording. Each audio callback mixes multi-channel input to mono, downsamples to 16kHz (integer decimation for common rates like 48kHz, rubato FftFixedInOut for fractional ratios like 44100Hz), and pushes samples into a shared `Arc<Mutex<Vec<f32>>>` buffer stored in `AudioSessionState`. When recording stops, the stop path drains that buffer instead of returning synthetic silence.

Key guarantees enforced:
- Hard cap at 4,800,000 samples (5 minutes at 16kHz) — buffer truncated and stop flag set
- Near-limit event `recording-near-limit` emitted once at 4,320,000 samples (4.5 minutes)
- Short recording rejection: recordings under 8,000 samples (0.5 seconds) return a user-friendly error
