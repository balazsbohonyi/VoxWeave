   ```rust
   fn start_realtime_level_capture<R: Runtime>(
       app: &AppHandle<R>,
       active_device: &str,
       pcm_buffer: Arc<Mutex<Vec<f32>>>,
   ) -> Result<(Arc<AtomicBool>, std::thread::JoinHandle<()>), String>
   ```

2. Inside the thread, after reading `default_config`, capture:
   ```rust
   let native_rate = stream_config.sample_rate.0;
   let needs_resample = native_rate != 16_000;
   ```

3. For each sample format branch (F32, I16, U16), extend the callback closure to:
   a. Convert samples to f32 (I16 and U16 already do this for RMS — reuse the same converted Vec)
   b. Resample to 16kHz if needed (see resampling note below)
   c. Lock `pcm_buffer`, push the resampled samples
   d. Check sample count: if `buf.len() >= 4_320_000` and NOT already emitted near-limit, emit `"recording-near-limit"` event once
   e. If `buf.len() >= 4_800_000`, truncate to 4_800_000 and set stop flag: `stop_for_thread.store(true, Ordering::Relaxed)`
   f. Unlock

   **Resampling note:** Use `rubato`. Create a `rubato::FftFixedIn::<f32>` resampler once before the stream is built (or use a per-chunk approach). Since rubato 1.x renamed types, use: `use rubato::{Resampler, SincFixedIn, SincInterpolationType, SincInterpolationParameters, WindowFunction};` — if that doesn't compile, fall back to `rubato::FftFixedIn` with the current 1.x constructor. The research notes the exact variant may need docs verification at impl time. If rubato 1.x constructor doesn't match, use a simple integer decimation for same-device rates that are multiples of 16000 (e.g., 48000→16000: keep every 3rd sample). Document the choice in a comment. Do NOT use linear interpolation for non-integer ratios — if rubato API is unclear, use the `samplerate` crate's `convert` function from the `samplerate` crate (add to Cargo.toml if needed) rather than hand-rolling. Priority: correctness over elegance.

   ```rust
   // Replace: let capture_pcm = synthetic_capture_pcm();

   };
   if capture_pcm.len() < 8_000 {

   ```
