# Phase 05.1 Plan 04: Surface Recording-Too-Short Error as In-Indicator Toast Summary

**"Recording too short" error now shows as an in-indicator toast via show_toast_window instead of silently hiding the indicator, with belt-and-suspenders emit_audio_error telemetry at the audio layer**

## Accomplishments
- Hotkey Err arm now calls `indicator::show_toast_window` with `TranscriptionErrorPayload{code: TooShort}` instead of silently calling `indicator::hide`
- `audio/mod.rs` too-short guard now calls `emit_audio_error` before returning `Err` — consistent with the `EncodeFailed` branch
- Added `TooShort` variant to `TranscriptionErrorCode` enum (was missing from codebase despite plan's interface spec listing it)

## Decisions Made
- Added `TooShort` variant to `TranscriptionErrorCode` — plan's interface spec listed it but it was absent from the actual code. Adding a new enum variant is correctness-critical (Rule 1) and non-architectural.
- Used `AudioErrorCode::EncodeFailed` for the audio-layer too-short emit since `AudioErrorCode` has no `TooShort` variant and the plan instructs to use whatever already exists.
