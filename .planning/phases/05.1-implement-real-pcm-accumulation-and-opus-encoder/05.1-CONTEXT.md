## Phase Boundary

Replace three stubs left from the Phase 3/5 implementation:
1. `synthetic_capture_pcm()` — returns 1 second of silence instead of real microphone audio
2. `DefaultEncoderBackend::encode_opus()` — returns a fake Ogg/Opus header, not real Opus frames
3. Missing log backend — `log::info!` calls exist throughout but nothing captures them

No new features. No UI changes. The output of this phase is audio that real transcription providers can actually decode.

</domain>

<decisions>
## Implementation Decisions

### Max recording duration
- Hard stop at 5 minutes; automatically proceed to transcription with captured audio (do not drop)
- Visual warning: indicator flashes at 4 min 30 sec (30 seconds before forced stop)
- After forced stop, encode and send as normal — user gets transcribed text even if truncated

### PCM accumulation
- Single cpal stream does both: computes RMS for the level indicator AND sends PCM chunks via mpsc channel to an accumulator
- No second stream open on the same device
- Resampling happens in the capture thread as chunks arrive (not at stop time), so the accumulation buffer is already at 16kHz
- If device natively reports 16kHz, skip resampling — detect at stream open and pass through directly

### Opus encoder library
- Use `audiopus` crate: safe Rust bindings to libopus, bundles and compiles libopus at build time (no separate install)
- Use `ogg` crate for Ogg container muxing around Opus frames (produces valid .ogg file)
- Both crates added to Cargo.toml; libopus compiled via existing MSVC + C toolchain

### Logging
- Use `tauri-plugin-log`: structured logging visible in Tauri devtools and written to a log file
- Log level: `Debug` in dev builds, `Info` in release builds

### Claude's Discretion
- Exact short-audio minimum threshold (Phase 3 decision still stands: short recordings warn and drop)
- Opus frame size and bitrate (use standard 20ms frames, 24kbps mono for voice)
- Resampling library choice (rubato recommended — pure Rust, high quality, no additional C deps)
- Exact log file path and rotation policy

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `audio/mod.rs: start_realtime_level_capture()` — already opens cpal stream and computes RMS in callback; extend this to also collect PCM chunks via a new mpsc sender
- `audio/mod.rs: stop_recording_and_encode_with_backend()` — already reads provider from config and calls encoder; replace `synthetic_capture_pcm()` call with real accumulated PCM retrieval
- `audio/encode.rs: DefaultEncoderBackend` — `encode_wav()` is real and correct; `encode_opus()` is the stub to replace
- `audio/encode.rs: EncoderBackend` trait — new real Opus implementation can replace DefaultEncoderBackend or be a new impl of the same trait
- `audio/session.rs: AudioSessionState` — will need to store the PCM accumulation channel receiver or `Arc<Mutex<Vec<f32>>>` buffer reference; currently only stores level emitter stop/join handles

### Established Patterns
- `#[cfg(not(test))] / #[cfg(test)]` guards separate real cpal code from test stubs — follow this pattern for real accumulation too
- Backend trait (`EncoderBackend`) already exists for encoder injection in tests — preserve this; the real Opus encoder is a new impl of the trait
- `arc::AtomicU32` for lock-free RMS sharing between callback thread and emitter loop — PCM uses mpsc channel instead (chunks, not atomic)

### Integration Points
- `audio/mod.rs: stop_recording_and_encode_with_backend()` — the only change needed at the call site is swapping `synthetic_capture_pcm()` for real accumulated PCM
- `audio/mod.rs: start_realtime_level_capture()` — extend the cpal callback to also send PCM to accumulator channel; return channel receiver alongside stop/join handles
- `state.rs: AudioSessionState` — store PCM receiver/buffer ref so `stop_recording_and_encode` can drain it
- `main.rs` or Tauri builder — add `tauri_plugin_log` to the plugin chain

</code_context>

<specifics>
## Specific Ideas

- The accumulator should enforce the 5-minute cap by tracking elapsed sample count (5 min × 16000 Hz = 4,800,000 samples). When the cap is reached, trigger the auto-stop path from the capture thread.
- Indicator flash at 4:30 can be implemented by emitting a new event (e.g., `recording-near-limit`) from the capture thread when accumulated samples cross 4.5 min threshold; frontend handles the visual change.

</specifics>
