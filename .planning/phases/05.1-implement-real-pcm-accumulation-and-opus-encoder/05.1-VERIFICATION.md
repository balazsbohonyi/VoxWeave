### Notable Deviation from Plan

**`AudioErrorCode` for too-short case:** Plan 04 specified `AudioErrorCode::TooShort` as the code for `emit_audio_error` in the too-short branch. The actual `AudioErrorCode` enum has only `NoInputDevice` and `EncodeFailed` — no `TooShort` variant. The implementation uses `AudioErrorCode::EncodeFailed` instead. This is not a functional gap: the event code is not used by any frontend handler (the `audio-error` event has no subscriber that branches on code), and the error is surfaced to the user as a toast via the separate `show_toast_window` path in `hotkey/service.rs`. The user-visible message is correct.
