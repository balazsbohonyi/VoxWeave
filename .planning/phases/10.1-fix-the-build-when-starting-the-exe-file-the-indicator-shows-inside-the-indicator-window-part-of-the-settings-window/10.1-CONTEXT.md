# Phase 10.1: Fix Build — Indicator Shows Settings Content - Context

**Gathered:** 2026-04-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the production .exe build so all four Tauri windows load the correct HTML. In dev mode Vite serves all HTML files from the project root directly (works). In production, only `dist/index.html` is built (no multi-page config), so indicator/wizard/toast windows all load settings content. No new features.

All three B002 symptoms resolve from this single root cause:
- Indicator shows Settings content
- Opening wizard from Settings opens a second Settings window
- Settings window opens from the tray (correct — it's the only file in dist)

</domain>

<decisions>
## Implementation Decisions

### HTML file naming and location
- Move all 4 HTML files from project root into `src/`
- Rename: `index.html` (Settings) → `src/settings.html`
- Rename: `indicator.html` → `src/index.html` (indicator becomes the main/default entry)
- `wizard.html` → `src/wizard.html`
- `toast.html` → `src/toast.html`
- Script `src` attributes inside HTML files use root-relative paths (`/src/windows/*/main.ts`) — no change needed

### Vite multi-page build config
- Add `build.rollupOptions.input` to `vite.config.ts` covering all 4 entry points using new `src/` paths
- No other Vite config changes needed

### Tauri window URL updates
- Update `tauri.conf.json` window URLs to match new paths: `src/index.html`, `src/settings.html`, `src/wizard.html`, `src/toast.html`

### Wizard-opens-Settings bug
- Same root cause as indicator showing settings content — not a separate code bug
- Resolves automatically once all HTML files are correctly built into dist

### Claude's Discretion
- Exact Vite rollupOptions key names
- Whether to add a build verification step (e.g., check dist contains all 4 HTML files)

</decisions>
