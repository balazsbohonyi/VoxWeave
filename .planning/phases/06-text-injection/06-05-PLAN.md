In `toggle_recording_state` in `src-tauri/src/hotkey/service.rs`, change the `else` branch of the `next_recording_state` check from a bare `return` to first setting `cancel_flag = true`, then returning.

Current code (lines ~225-229):
```rust
if let Some(next) = next_recording_state(&previous) {
    *recording_state = next;
} else {
    return;
}
```

Change the `else` branch to:
```rust
} else {
    // Hotkey pressed while injection is in progress — signal cancel.
    // The cancel_flag is polled by keystroke_inject() between each character.
    // For FlashPaste/Clipboard modes this is a no-op (cancel_flag is never polled),
    // but setting it is harmless and covers future injection modes.
    drop(recording_state); // release the lock before acquiring cancel_flag lock
    *state.cancel_flag.lock().unwrap() = true;
    return;
}
```

Note: `recording_state` is a MutexGuard held inside the block — it must be dropped before locking `cancel_flag` to avoid deadlock. Use `drop(recording_state)` explicitly before acquiring the cancel_flag lock.

Also update the unit test for `next_recording_state` (already exists in `#[cfg(test)]` at bottom of file) to add a test verifying the cancel path. Add a new test function `toggle_recording_transcribing_sets_cancel_flag` that:
1. Creates a minimal AppState (or uses the existing test helper pattern in this file)
2. Sets recording_state to Transcribing
3. Calls toggle_recording_state (or directly tests the cancel_flag logic inline)

If constructing a full AppHandle is not feasible in unit tests (Tauri AppHandle is not easily mocked), add the test as an integration note and verify via `cargo test hotkey` passing the existing tests — the behavioral fix is verifiable by the keystroke_cancel test in injection/service.rs which already tests the cancel_flag polling path.
