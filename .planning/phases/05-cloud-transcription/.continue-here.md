<remaining_work>

**Bug 1 — Toast does not appear (invalid_key case):**
Root causes identified:
1. `hotkey/service.rs` Err(()) branch calls `indicator::show_idle(&app_clone)` — this re-shows the indicator immediately after show_toast_window hid it, fighting with the toast lifecycle. Fix: only call show_idle if toast window is NOT visible.
2. Event delivery to hidden windows is unreliable in Tauri v2/WebView2. Fix: use `toast_win.eval("window.__voxflowShowToast && window.__voxflowShowToast({...})")` instead of `app.emit("transcription-error")` to deliver payload directly to the toast window after showing it.

Changes needed:
- `hotkey/service.rs` line ~274: `Err(()) => { let _ = indicator::show_idle(&app_clone); }` → check if toast window is visible first, only call show_idle if not
- `indicator/mod.rs` `show_toast_window`: after `toast_win.show()`, call `toast_win.eval(format!("window.__voxflowShowToast && window.__voxflowShowToast({})", serde_json::to_string(&payload).unwrap()))` — requires adding payload parameter
- `transcription/service.rs` `emit_transcription_error`: pass payload to show_toast_window (not just call without args), remove or keep app.emit for cancelled case
- `src/windows/toast/App.vue`: remove `listen("transcription-error", ...)` listener, instead expose `window.__voxflowShowToast = (payload) => { ... }` global in onMounted. Also remove `invoke("show_toast_window")` call from frontend.
- `commands/indicator.rs`: show_toast_window command no longer needed from frontend (keep hide_toast_window)

**Bug 2 — Indicator height 180px:**
Root cause: `set_resizable(true)` in resize_window causes Windows to expand the window when WS_THICKFRAME is temporarily added. My earlier "fix" of always calling resize_window in show_with_state was MAKING IT WORSE.

Current state: Already reverted the bad change (show_with_state no longer always calls resize_window). But startup lib.rs still has the resize_window call for the indicator which is also triggering the 180px issue.

Fix needed:
- `lib.rs`: Remove the `indicator::window::resize_window(...)` call in setup (lines ~57-61). The indicator is always 70px from tauri.conf.json, no need to resize. The old expand code is gone so there's nothing to reset.

</remaining_work>

<decisions_made>

- Separate toast window approach (not inline in indicator) — user requirement
- Use eval() not events to deliver toast payload to toast window — more reliable for hidden windows

- Toast window uses window.__voxflowShowToast global (not Tauri events)
- hide_toast_window calls show_idle to restore indicator after toast dismissal
