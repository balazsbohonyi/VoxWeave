Three targeted single-line edits to src-tauri/src/hotkey/service.rs:

EDIT 1 -- Line 97 (startup failure path):
Change:
  emit_hotkey_warning(app, &warning, HotkeyWarningSource::Startup, true);
To:
  emit_hotkey_warning(app, &warning, HotkeyWarningSource::Startup, false);

Rationale: On startup the user has not asked for Settings; opening it uninvited is the bug.
The hotkey-warning event is still emitted so the frontend can show a non-intrusive toast.

EDIT 2 -- Line 198 (save/re-register failure path):
Change:
  emit_hotkey_warning(app, &warning, HotkeyWarningSource::Save, true);
To:
  emit_hotkey_warning(app, &warning, HotkeyWarningSource::Save, false);

Rationale: The warning event is enough; forcibly opening Settings surprises the user
during a config-save operation.

EDIT 3 -- Inside the async spawn block, Err(()) branch (~line 274):
Change:
  indicator::hide(&app_clone);
To:
  let _ = indicator::show_idle(&app_clone);

Rationale: The transcription-error Tauri event is emitted inside transcribe_with_retry
but the JS event loop has not yet delivered it when hide() runs. The indicator disappears
before the toast renders. show_idle() keeps the window visible (in idle visual state) so
the event loop delivers the toast. The frontend will call hide_indicator once the toast
is dismissed (Task 2).

No other logic changes. All three are single-line replacements.
